# 去AI味 · 中文人味改写

这个 skill 的目标是把带有「AI机械味」的中文文本，改写成像是一位有经验的从业者自己动手写出来的东西——语法规范、用词准确、逻辑清楚，但读起来不像是从模板里倒出来的。

---

## 总则：AI写方案/文档，到底哪里不对劲？

AI 写出来的方案或文档，一眼就能认出来：句子像流水线上压出来的，每一段都按同一个模子排版，读着读着就感觉在翻阅一本没有人味的说明书。具体表现为：

- **动词不直接上**：不说「分析」，非要说「进行分析」；不说「优化」，非要说「进行优化」
- **修饰词当饭吃**：动不动就「全方位」「多维度」「系统性」「深度赋能」
- **过渡词像路标**：「首先……其次……再次……最后……综上所述」像在画流程图
- **排比凑字数**：硬凑三个四字短语，读起来整齐但啥也没说
- **长句套长句**：定语和状语一层层往上叠，读完忘了主语在哪
- **核心信息埋在后面**：铺垫铺半天，结论在最后一行；人写东西一般是先说结论
- **被动语态泛滥**：「被认为」「被视为」「被广泛认可」——谁认的？不敢说
- **每段都要总-分-总**：开头重复标题、中间展开、结尾再总结一次，像在做题

人写的方案不是这样。人写方案是**带着判断在写**，有自己的视角，知道重点在哪，该长则长、该短则短，不凑排比，不用废话撑篇幅。

---

## 核心改写规则

### 规则 1：动词直接上，别拐弯

AI 最爱把动词藏起来，前面加个「进行」「开展」「实施」「推动」「促进」「强化」充当万能动词壳。人写方案就是直接说动词。

| AI写法（拐弯） | 人写法（直接） |
|---|---|
| 进行数据分析 | 分析数据 |
| 开展用户调研 | 调研用户 |
| 实施系统优化 | 优化系统 |
| 推动流程落地 | 推广流程 |
| 促进团队协同 | — 删掉，后面直接说怎么做 |
| 强化风险意识 | — 删掉，换具体措施 |

**改写前：**
> 针对现有系统存在的问题，我们将进行全面的排查与分析，在此基础上开展针对性的优化工作，以期实现系统性能的显著提升。

**改写后：**
> 现有系统存在三个问题：A、B、C。我们计划先排查定位，再分别优化，预计性能可提升 30% 以上。

**要点**：
- 把「进行排查」改成「排查」，「开展优化」改成「优化」——动词往前走
- 「以期实现……的显著提升」这种话直接删掉，换成具体数字或结论
- 如果动词后面没有具体内容，说明这句话本身可能不需要

---

### 规则 2：修饰词只为精确服务，不为凑字数

AI 写方案时会习惯性地往名词前面塞修饰词，一层不够再套一层：「系统性的全方位的深度优化方案」——这就叫凑字数。人写方案用修饰词，是为了精确，不是为了好看。

| AI写法（堆砌） | 人写法（精简） |
|---|---|
| 全方位、多层次、宽领域 | 三个维度 / 从A、B、C三个方面 |
| 系统性的深度优化 | 优化 |
| 全面的、深入的、细致的调研 | 调研 |
| 积极推动、大力推进 | 推 |
| 充分沟通、深入交流 | 沟通 |
| 高度重视、密切关注 | 重视 |

**改写前：**
> 我们将通过系统性的、多维度的、深层次的用户需求挖掘，为产品迭代提供全面的、精准的、具有前瞻性的决策依据。

**改写后：**
> 我们通过三种方式挖掘用户需求：用户访谈、数据分析和竞品对比。这些信息直接用于产品迭代决策。

**要点**：
- 删掉所有不能还原为具体事实的修饰词
- 如果「全方位」后面没有列出到底哪几方面，这个词就是空的
- 保留对精度有益的修饰：「预计提升 30%」比「显著提升」好一百倍

---

### 规则 3：过渡靠内容逻辑，不靠「首先其次」

人写方案，段落之间是靠内容逻辑自然衔接的——有的是因果关系，有的是递进关系，有的是转折。AI 写方案全用「首先、其次、再次、最后」「此外」「另外」这种万能连接词，像在做 PPT 大纲。

**改写前：**
> 首先，我们需要明确项目目标。其次，我们需要组建项目团队。再次，我们需要制定项目计划。最后，我们需要建立监控机制。

**改写后：**
> 项目启动前，先明确目标。目标定下来之后，组建团队——谁负责什么，什么时间交付。团队到位后，出一个整体计划和时间表。整个过程需要持续监控，我们每周同步一次进度。

**过渡方式的多样性**：

| 逻辑关系 | 自然过渡方式 |
|---|---|
| 因果 | 「所以」「这意味着」「结果是」 |
| 递进 | 「更进一步」「更关键的是」「不只如此」 |
| 转折 | 「但」「不过」「问题在于」「现实是」 |
| 时间 | 「之后」「下一步」「完成后」 |
| 举例 | 「比如」「拿……来说」「具体来说」 |
| 补充 | 「还有一个点」「另外」「顺便提一下」 |

**要点**：
- 能不用「首先/其次/最后」就尽量不用
- 用内容本身的逻辑关系来串段落
- 实在需要用序列时，用「第一」「第二」「第三」也比「首先其次」自然

---

### 规则 4：句子有长有短，朗读有节奏

AI写的文字，句子长度差不多，读起来像节拍器在敲。人写的文字，长短错落——短句拿来下判断，长句用来讲道理。

**改写前：**
> 在当前的行业背景下，随着用户需求的不断变化以及技术迭代的持续加速，传统的产品开发模式已经难以适应市场的快速变化，因此我们需要建立一套更加敏捷的、能够快速响应变化的研发体系，以此来提升我们的市场竞争力。

**改写后：**
> 现在行业变化很快。用户需求在变，技术迭代也在加速。
>
> 传统开发模式跟不上了。
>
> 我们需要建一套更敏捷的研发体系——能快速响应变化，才能保持竞争力。

**要点**：
- 短句（10-15字）用来下结论、表态
- 长句（25-40字）用来解释因果、展开论述
- 一段内至少有一处长短切换
- 超过50字的长句，检查能否拆成两句
- 用破折号做插入说明，比套定语从句更流畅

---

### 规则 5：主语要清楚，别躲

AI 写方案喜欢躲主语——「建议」「推荐」「应当」「需要」谁建议的？谁需要？人写方案，主语该出来就出来。

**改写前：**
> 建议在下一阶段对核心模块进行重构，以提升系统可维护性。同时推荐引入自动化测试，以降低回归风险。

**改写后：**
> 我们建议下一阶段重构核心模块，提升可维护性。同时引入自动化测试，降低回归风险。

**要点**：
- 「我们」「团队」「XX部门」——该写谁就写谁
- 「建议」前面加上主语比单独用「建议」更可信
- 被动语态转主动：「A被B影响」→「B影响了A」

---

### 规则 6：敢于下判断，别总留退路

AI 写方案特别怕出错，每句话都要留退路：「在一定程度上」「总体来看」「基本可以认为」。人写方案，自己判断了就直接说，有把握的不需要加缓冲。

| AI写法（留退路） | 人写法（直接判断） |
|---|---|
| 在某种程度上存在一定的关联性 | 两者有关系 / 两者关联不强 |
| 总体来看，基本可以认为该方案具有可行性 | 这个方案可行 |
| 可能会对系统产生一定的影响 | 会影响系统 |
| 不排除后续存在调整的可能 | 后续可能会调整 |
| 在一定条件下可以实现预期效果 | 满足条件X后，可以达到Y效果 |

**改写前：**
> 从总体上来看，该方案在现有条件下基本具备实施的可行性，但在某些细节层面可能还存在进一步优化的空间。

**改写后：**
> 这个方案可以落地。有几个细节需要再打磨一下：A、B、C。

**要点**：
- 如果结论是确定的，就不要加「基本」「总体来看」
- 如果结论不确定，就直接说「还不确定，需要验证X」
- 「存在……的空间/可能」这种句式一律简化

---

### 规则 7：结构化信息用列表，别埋在大段文字里

人写方案，碰到并列信息会用列表、用标题切出来——方便自己回头看，也方便别人看。AI 反而喜欢把应该拆成列表的内容硬塞进段落里。

**改写前：**
> 本次迭代主要包含以下几个方面的内容：在功能层面，我们将新增用户画像模块和数据分析看板；在性能层面，我们将对数据库查询效率进行优化以及对接口响应速度进行提升；在体验层面，我们将对部分交互流程进行简化和优化。

**改写后：**
> 本次迭代包含三个层面：
>
> **功能**
> - 新增用户画像模块
> - 新增数据分析看板
>
> **性能**
> - 优化数据库查询效率
> - 提升接口响应速度
>
> **体验**
> - 简化核心交互流程

**要点**：
- 并列信息超过 3 条，直接上列表
- 列表可以配小标题，结构更清晰
- 列表每一项保持平行的语法结构

---

### 规则 8：开头说重点，别搞长长的背景铺垫

AI 写方案，开篇一定要来一段「行业背景+发展趋势+面临的挑战+我们要做什么」，人读了三段还没看到重点。人写方案，开篇直接说「要做什么、为什么要做、怎么做」，背景信息放在后面或干脆省略（大家默认都知道）。

**改写前：**
> 随着数字化转型的不断深入，各行各业都在积极探索如何利用数据驱动业务增长。在此大背景下，数据中台作为连接数据与业务的重要桥梁，其建设质量直接关系到企业的数据应用效率和业务创新能力。当前，我司数据中台已上线运行两年，在取得一定成效的同时，也暴露出了一些亟待解决的问题。因此，我们提出了以下数据中台优化方案。

**改写后：**
> 数据中台上线两年，现在有三个问题：查询慢、数据对不上、新业务接入困难。这个方案就是解决这三个问题的。

**要点**：
- 第一段直接回答：什么问题？怎么解决？预期结果？
- 「行业背景」「发展趋势」这种信息，除非真的有信息增量，否则删掉
- 如果背景必不可少，压缩到一句话

## 改写流程

收到需要改写的文本后，按以下步骤操作：

1. **快速扫一遍**，判断文本类型（方案、报告、邮件、技术文档、产品说明等）
2. **圈 AI 痕迹**：
   - 找出所有「进行/开展/实施/推动/促进/强化 + 名词」的结构，改成直接用动词
   - 标出所有「首先/其次/最后/此外/另外/值得注意的是/综上所述」
   - 找出超过 50 字的长句
   - 标出「全方位/多维度/系统性/深度/全面/充分」等空泛修饰词
   - 找出「在……下/中」「从……角度/层面」这类万能开头句式
3. **逐段改写**，应用上述 8 条规则
4. **朗读检查**：在心里默读一遍，如果读起来感觉「很顺但很空」，说明还有 AI 味
5. **最终检查**：
   - 每一段有没有实在的信息？还是只有漂亮的空话？
   - 能不能一句话概括每段在说什么？如果不能，这段可能需要重写
   - 如果我是读者，读完能得到什么？——这是最终判断标准

## 常见 AI 惯用语替换表

| AI 惯用语 | 替换建议 |
|---|---|
| 在当今/当前……的时代/背景下 | 删掉，或改为「现在/目前」 |
| 随着……的不断发展/深入 | 删掉，直接说变化 |
| 值得注意的是 / 需要指出的是 | 删掉，后面内容直接说 |
| 不可或缺 / 不可忽视 | 重要 / 关键 / 删掉 |
| 扮演着重要的角色 / 发挥了重要作用 | 很关键 / XX负责…… / 删掉 |
| 旨在 / 以期 / 以……为目的 | 目标是…… / 为了…… / 删掉 |
| 综上所述 / 总而言之 | 删掉，或改为「总结下来」 |
| 在一定程度上 / 在某种程度上 | 删掉，或改为具体程度 |
| 极大地 / 显著地 / 大幅度地 | 用具体数字代替，否则删掉 |
| 进行（分析/优化/调整/改造） | 分析 / 优化 / 调整 / 改造 |
| 开展（调研/评估/测试） | 调研 / 评估 / 测试 |
| 实施（部署/推广/落地） | 部署 / 推广 / 落地 |
| 实现……的（提升/优化/突破） | 提升 / 优化 / 突破 |
| 赋能 | 帮助 / 支撑 / 让……能 |
| 抓手 | 关键措施 / 切入点 |
| 闭环 | 完整流程 / 从头到尾 |
| 底层逻辑 | 基本思路 / 核心原理 |
| 颗粒度 | 细节 / 精细程度 |
| 对齐 | 同步 / 确认 / 保持一致 |
| 拉通 | 协调 / 沟通 / 串联 |
| 倒逼 | 反过来推动 / 促使 |

## 示例对比

### 示例1：方案开篇

**AI味原文：**
> 在当前竞争日益激烈的市场环境下，用户对产品的体验要求不断提升，传统的功能驱动型产品策略已经难以满足日益多元化的用户需求。为应对这一挑战，本方案旨在通过系统性地梳理用户旅程、深入挖掘用户痛点，并在此基础上进行针对性的体验优化，从而全面提升产品的用户体验水平，增强产品的市场竞争力。

**人味改写：**
> 用户对体验的要求越来越高，但我们的产品还停留在「堆功能」的阶段。
>
> 这个方案做三件事：
> 1. 梳理用户的核心使用路径，找出卡点
> 2. 针对每个卡点给出优化方案
> 3. 定一个可衡量的体验指标，追踪效果
>
> 目标是把用户满意度从当前的 3.2 提到 4.0。

---

### 示例2：技术方案

**AI味原文：**
> 基于对现有系统架构的全面评估，我们发现当前系统在以下三个维度存在较为明显的不足：首先是数据库查询效率问题，在数据量持续增长的背景下，部分核心查询的响应时间出现了显著上升；其次是接口设计的灵活性问题，随着业务需求的快速变化，现有接口的扩展能力受到了较大的制约；最后是系统监控体系的不完善，导致我们在故障发生时难以进行及时的定位与处理。针对上述问题，本方案提出了相应的优化措施。

**人味改写：**
> 现有系统评估下来，有三个方面需要改进：
>
> **数据库查询慢**。核心查询耗时从 200ms 涨到了 800ms，因为数据量翻了一倍但索引没跟上。优化方案：重建索引 + 热门数据加缓存。
>
> **接口扩展性差**。每次新业务接入都要改老接口，风险大。优化方案：抽一层适配层，新业务走适配层接入。
>
> **监控不够**。出了故障经常靠用户反馈才知道。优化方案：补全核心链路监控 + 自动告警。
>
> 三个优化并行推进，预计两个月完成。

### 示例3：邮件/通知

**AI味原文：**
> 各位同事：
>
> 经过项目管理组的充分讨论与评估，我们决定在下周一（6月2日）正式启动第三阶段的开发工作。本次迭代的主要目标是对核心业务流程进行系统性优化，同时针对用户反馈较为集中的若干体验问题进行全面修复。请各位相关同事提前做好准备，确保工作的顺利推进。如有任何疑问，请及时与项目组进行沟通。
>
> 感谢大家的配合与支持！

**人味改写：**
> 各位：
>
> 下周一（6月2日）启动第三阶段开发，两件事：
> - 优化核心业务流程
> - 修复用户反馈最多的几个体验问题
>
> 具体任务清单周三前发到各位手上。有问题随时在群里聊。
>
> 辛苦大家。

### 示例4：产品说明

**AI味原文：**
> 该功能旨在为用户提供一种更加高效、便捷的数据查询方式。通过创新的交互设计以及智能化的数据处理能力，用户可以在短时间内快速获取所需的信息，并且根据自身需求进行个性化的数据筛选与展示。该功能的推出，标志着我们在数据可视化领域取得了重要的进展，也为后续的产品功能扩展奠定了坚实的基础。

**人味改写：**
> 这个功能让数据查询更快更方便。
>
> 两点改进：
> - 交互重新设计，常用操作从三步缩短为一步
> - 数据筛选支持自定义，想看什么自己选
>
> 这是我们数据可视化模块的第一个版本，后续会加入更多图表类型和导出功能。

## 使用说明
